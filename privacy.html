Privacy and Google API data

Privacy policy

Effective 16 October 2026. This policy describes the owner-operated NexPOS Backup desktop workflow and its use of Google Drive.

Who this is for

NexPOS Backup is currently a private utility operated by the NexPOS project owner. It is not a customer-facing sign-in product. The website itself is a static informational page hosted by GitHub Pages.

Google information and permissions

The desktop integration uses Google's drive.file OAuth scope to create, locate, upload, download, verify, and remove files managed by or expressly authorized for the app. It may process Google Drive file IDs, file names, sizes, timestamps, and transfer status needed for that purpose. The operator authorizes access through Google's consent screen.

OAuth credentials and refresh tokens are stored in the operator's local rclone configuration. They are not collected by this website. Tokens should be protected by local file permissions and revoked if exposed.

Backup content

When the owner explicitly enables production backups, an approved database export is first encrypted locally with restic before the resulting repository files are copied to Google Drive. Google Drive receives encrypted repository objects, not intentionally unencrypted production database exports. File and folder names, sizes, access logs, and related Google Drive metadata may remain visible to Google.

The restic recovery password is managed separately by the operator; it is not stored in this website or provided to Google as part of the transfer workflow. The owner must retain a secure recovery copy of that password independently.

How data is used

Google user data is used only to operate the requested personal backup, verification, recovery, and cleanup workflow. It is not sold, used for advertising, or used to train AI models. This website does not include advertising, client-side analytics, or Google sign-in forms.

Google Drive itself stores files under the operator's Google account. GitHub Pages may process ordinary website request information under GitHub's own privacy practices.

Sharing, retention, and deletion

We do not intentionally share backup content with unrelated third parties. Backup repository files are stored privately in the operator's designated Drive account and the approved local encrypted-backup location. The owner controls the backup schedule and retention; automatic production backup scheduling has not yet been enabled. The owner can delete managed files from Drive and local storage and revoke Google access from Google Account settings at any time. Deletion is subject to Google's trash, retention, and provider policies.

Security and limits

Restic provides authenticated encryption for backup content. A successful restore still depends on retaining the correct recovery password, uncorrupted repository files, and access to compatible recovery tools. No security control guarantees against every possible failure.

Contact

For privacy questions, contact the app owner using the developer contact shown on the Google OAuth consent screen. For public, non-sensitive policy corrections, use GitHub issues without disclosing personal or confidential information.

Updates

We will update this page when production backup practices, retention arrangements, permissions, or data handling materially change.
